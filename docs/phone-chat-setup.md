# "Chat on phone" — setup, deployment and verification

How the web-only phone chat feature works, what the repository owner must
configure before it works against live Twitch, and what was verified during
implementation (October 2026).

## What it does

- While watching a **primary live stream** (normal playback or
  picture-in-picture) the player controls include **Chat on phone**. It opens
  a dialog with a locally generated QR code and a readable fallback URL.
- Scanning the code opens a standalone mobile page,
  `phonechat.html`, locked to **the channel selected at scan time**. Changing
  streams on the TV does **not** change an already open phone page: scan again.
- The phone performs its **own independent Twitch login** (browser implicit
  flow). TV tokens are never transferred through the QR link; the link only
  ever carries `?channel=<login>`.
- The page reads and writes chat over Twitch IRC (secure WebSocket) and
  supports **Twitch, BTTV, FFZ and 7TV emotes**, both in received messages and
  in a searchable emote picker. Login is required in V1 (no anonymous preview).
- The session lives in **sessionStorage of the same tab**: a reload in the
  same tab keeps the login; closing the tab signs out.
- Hidden in multistream, VOD and clip playback. No secondary-channel selection
  in V1.

## OWNER SETUP REQUIRED (blocking live OAuth)

The feature builds and runs today, but sign-in on the phone stays in a visible
"not configured" state until the owner completes:

1. **Register a Twitch developer application** owned by this fork
   (<https://dev.twitch.tv/console>) with a browser/SPA client type (no
   secret). Do not reuse an upstream client ID; its owner cannot register this
   page's callbacks.
2. **Register these exact callback URLs** (scheme, host, path, case):
   - `https://yofardev.github.io/SmarterTwitchTV/release/phonechat.html` (GitHub Pages — the canonical QR target, already the host the APK uses)
   - `https://smarttv-client-for-twitch.web.app/phonechat.html` (only if that Firebase site is actually enabled/owned and you add the origin to `PhoneChatConfig.allowedOrigins` plus the path to `allowedPaths`)
   - For development, a *reachable* HTTPS test origin (a phone cannot reach
     the developer computer's `http://localhost:5000`; Twitch also restricts
     localhost — check current policy before relying on it).
3. **Put the client ID** into `PhoneChatConfig.clientId` in
   `app/general/PhoneChatConfig.js` and rebuild (`node release/scripts/maker.js`).
4. **Publish** `release/` through the existing hosting workflow, then verify
   `https://yofardev.github.io/SmarterTwitchTV/release/phonechat.html` loads
   before advertising the TV action.

Required scopes (already coded, do not expand without need):
`chat:read chat:edit user:read:emotes`.

## Development

- Source page in a browser: serve the repo root and open
  `/app/PhoneChat/index.html?channel=<login>` (the source page loads its own
  `phonechat.css` — no prior build needed), or test the built page at
  `/release/phonechat.html?channel=<login>`.
- Focused logic checks: `node release/scripts/phonechat-tests.js`
  (259 assertions: channel/URL building, OAuth callback + token validation,
  complete app boot flows (mock DOM: callback return, denial, tampered state,
  replay, unavailable storage, expired session), IRC parsing including the
  untagged auth-failure notice, outbound validation, emote
  normalization/collisions/overlays with the documented Get User Emotes shape,
  bounded rendering with deletion replay, moderation transitions with
  controllable timers, and slow-mode change notices). Lifecycle regressions
  dispatch offline/online and pagehide/pageshow and join replacement sockets;
  they check preserved history/deletions/echoes, disabled composer states,
  restored timeout/ban explanations, and expiry while offline.
- After rebuilding, run `node release/scripts/phonechat-tests.js --built`
  to exercise the same app flows against the generated minified phone bundle
  (pure helper checks continue to use source).
- Full build + lint: `node release/scripts/maker.js jsh` then
  `node release/scripts/maker.js` (lint failures exit non-zero).

## Verification status (October 9 2026)

Verified during implementation and the review-repair pass:

- `maker.js jsh` and full build pass; generated page references the phone
  bundle/minified CSS; the TV bundle contains the QR dialog code but none of
  the phone runtime; `version.json` bumped to WebTag 742.
- The assertion harness above passes (259/259), including boot flows that load
  `main.js` with a mock DOM and drive the full OAuth return → validation →
  chat-join chain. The `--built` run also passes 259/259, with app flows loading
  the generated bundle. Reconnects retain the feed's bounded dedup/deletion
  store and local echo tracking; actual lifecycle regression tests cover
  timeout and permanent-ban status restoration on a replacement socket.
- Twitch emote CDN URL shape verified without credentials: real emote ids
  return 200 for `/static/dark/2.0` and 404 for the bare `/2` form. The
  documented HypeLol ID is `304420818`; the fixtures now include that entry
  with the actual decimal scale array. Synthetic bare-scale fixtures test
  compatibility separately.
- Browser-checked (real browser, local HTTP server): the source page styles
  itself from its own CSS and boots; the generated page honors the `hidden`
  attribute on the picker and banner (open/close/dismiss all change computed
  `display`); the source TV entry page loads the three new scripts (200s).
- QR rendering logic exercised locally (auto-sized QR-M with 4-module quiet
  zone, sharp canvas cells).

NOT yet verified against live Twitch (requires the owner setup above, plus a
real account/device):

- Real Twitch login on the phone (implicit flow + `/oauth2/validate`).
- Sending/receiving chat on a real channel, slow mode/rejections, deletions.
- BTTV/FFZ/7TV CORS from the deployed origin and live emote rendering.
- Physical QR scan from a TV at viewing distance.
- Mobile browsers: keyboard/IME, orientation, safe areas, background/resume.
